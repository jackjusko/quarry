# Follow-Up

On-demand. Does **not** send messages unless the user explicitly asks you to send via browser/email in this session.

## Read first

- [`pipeline/tracker.md`](../../../pipeline/tracker.md)
- Relevant `pipeline/packets/<id>/` (JD, cover letter, handoff)
- [`pipeline/candidate-profile.md`](../../../pipeline/candidate-profile.md) — sign with full name; contact from profile
- **write-well** companions under [`../write-well/`](../write-well/) before drafting

## When to follow up

Typical triggers (user may override):

- No reply **7–10 days** after apply
- After a screen or onsite (thank-you within **24 hours**)
- Recruiter went quiet mid-process (**4–5 business days**)

## Workflow

1. Identify target rows in the tracker (`applied` / `interview`) or packet ids from the user.
2. Draft **one** short message per target (email or LinkedIn — match the channel they used).
3. Save drafts under the packet as `follow-up-<YYYYMMDD>.txt` or show inline if the user prefers.
4. If the user confirms they sent it, update tracker notes + `updated` date.

## Message shape

- **2–6 sentences**
- Remind them of role + date applied
- One concrete value add or question (not “just checking in” alone)
- No guilt, no essays, no “passionate about your mission”
- Sign with full name from candidate-profile

## Examples of substance

- Point to a relevant shipped outcome from the pool in one line
- Ask a specific process question (“Is there an updated timeline for the next interview stage?”)

## Hard rules

- **write-well** — no AI fluff
- Do not spam multiple follow-ups the same week unless the user insists
- Do not auto-send
- No hardcoded PII — read contact and name from profile
